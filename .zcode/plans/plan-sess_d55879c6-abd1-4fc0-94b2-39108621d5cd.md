# BTViewer 功能扩展计划(8 项,分 6 个阶段递增交付)

已确认的关键约束:下载引擎是 **aria2c 子进程(JSON-RPC)**,其 RPC 不提供逐 peer/逐 tracker 状态,故"任务详情"展示文件明细与聚合数据而非 peer 列表;缩略图采用**渲染层截帧**方案,不引入 ffmpeg 依赖。

---

## 阶段 1:播放器增强(倍速播放、音量记忆、本地字幕)

**1a. 倍速 + 音量记忆** — 改 `src/components/Player.tsx`
- video.js 初始化 options 加 `playbackRates: [0.5, 0.75, 1, 1.25, 1.5, 2]` 与 `controlBar.playbackRateMenuButton`(自带倍速菜单 UI)
- 沿用现有 `btviewer-autoplay` 的 localStorage 模式:新增 `btviewer-volume`、`btviewer-rate` 两个 key,`loadedmetadata` 时应用、`volumechange`/`ratechange` 事件节流持久化(全局记忆,跨任务生效)

**1b. 本地字幕加载** — 改 `Player.tsx`
- 播放器头部字幕选择器旁加"加载字幕…"按钮,隐藏 `input[type=file]` 选 `.srt/.vtt`
- FileReader 读文本;把 `electron/torrent-engine.ts` 里的 srt→vtt 转换逻辑抽到共享模块(如 `src/services/subtitle.ts`,主进程与渲染层共用),`URL.createObjectURL` 生成 blob 后走现有 `addRemoteTextTrack` 通道,并入 `subtitleItems` 列表统一切换
- 无需新增 IPC;CSP 已允许 blob

## 阶段 2:健壮性(设置即时校验、ErrorBoundary)

**2a. 设置即时校验** — 改 `src/components/Settings.tsx`
- trackers(逐条校验协议前缀)与限速格式改为输入时校验,错误时输入框红框 + 下方提示文案,有错时禁用保存按钮(现有点保存才报错)

**2b. 错误边界** — 新增 `src/components/ErrorBoundary.tsx`
- class 组件捕获子树渲染异常,展示错误信息 + "重新加载"按钮(调 `location.reload`);在 `App.tsx` 包住 `content` 区域,避免播放器/列表异常导致白屏

## 阶段 3:托盘最小化 + 开机自启

**3a. 关闭最小化到托盘** — 改 `electron/main.ts`、`electron/settings.ts`、`Settings.tsx`
- `AppSettings` 加 `closeToTray?: boolean`(默认 true);设置页加开关
- `mainWindow.on('close')`:开启时 `preventDefault()` + `hide()`,复用现有 `isQuitting` 标志;新增托盘图标(复用应用 icon)+ 菜单:显示主窗口 / 退出(置 `isQuitting=true` 再 close,确保 aria2 清理逻辑 `shutdown()` 正常触发)
- 启动参数 `--hidden` 时创建窗口后不显示(配合自启)

**3b. 开机自启** — 改 `electron/main.ts`、`settings.ts`、`Settings.tsx`
- `AppSettings` 加 `launchOnStartup?: boolean`;`settings:set` 时调 `app.setLoginItemSettings({ openAtLogin, path: process.execPath, args: ['--hidden'] })`,回显用 `getLoginItemSettings()`

## 阶段 4:任务详情面板

- 扩展 `electron/torrent-engine.ts`:导出任务详情(磁力、infoHash、下载目录 `status.dir`、上传累计 `uploadLength`、已配置 tracker 数从 magnetURI `tr=` 解析);**aria2 无逐 peer/tracker 状态,界面明示"引擎不提供"**
- `DownloadManager.tsx` 卡片加"详情"展开区:状态、速度、连接数、分享率(uploaded/downloaded)、保存路径 + "打开目录"、每文件进度明细表(复用 FileList 的 `file-table` 样式)

## 阶段 5:媒体库缩略图(渲染层截帧,无 ffmpeg)

- 新增 `src/services/thumbnail.ts`:隐藏 `<video>` 加载现有 streamUrl(muted、preload=metadata),`loadedmetadata` 后 seek 到 `min(duration*0.2, 45s)`,`seeked` 时 canvas `drawImage` 缩放到 320px 宽输出 `dataURL(jpeg)`;8s 超时或报错记为失败(负缓存,避免反复重试);并发上限 1 的队列
- 新增 `electron/thumbnail-store.ts` + IPC `thumb:get/save`:dataURL 存 `{userData}/thumbnails.json`(参照 progress-store 模式)
- `FileList.tsx`:任务 tile 与文件表 video 行展示缩略图(失败回退现有图标);CSP 的 `img-src` 已含 `data:` 无需改
- 主进程 HTTP 流已有 Range 支持,边下边播文件头部就绪即可截帧

## 阶段 6:RSS 追剧订阅(完整版)

**6a. 主进程** — 新增 `electron/rss.ts`
- 订阅存储 `{userData}/feeds.json`:`{ id, name, url, keywords[], saveMode, enabled, lastGuids }`;XML 解析引入 `fast-xml-parser` 轻量依赖
- 轮询(默认 15 分钟,可配):拉取 feed → 提取条目中的磁力/种子链接 → 关键词匹配 → 自动 `addTorrent`
- 自动归类:标题解析 `SxxExx`/`第x季` 等,按"订阅名/Sxx"建子目录(需给 `torrent-engine.addTorrent` 增加 `dir` 参数,aria2 `addUri` 原生支持)
- 下载完成桌面通知:引擎检测到任务变 complete 时 `new Notification()`;`settings:set` 需处理 Windows 通知 appUserModelId

**6b. 渲染层** — 新增 `src/components/Feeds.tsx`
- 侧边栏加"订阅"入口;页面含:订阅源列表(名称/URL/关键词/开关/删除/立即刷新)、添加订阅表单、每个订阅的最近抓取条目与"手动下载"按钮
- 相关状态与操作通过新 IPC(`feeds:list/add/remove/toggle/refresh`)+ preload 暴露

## 每阶段验收

- 每阶段结束:`npm run typecheck` + `npm test` + `npm run build` 全绿
- 单元测试:阶段 1 补 srt→vtt 转换测试,阶段 6 补 RSS 链接提取、关键词匹配、SxxExx 解析测试(沿用 vitest,引擎测试已有 18 个)
- 涉及文件:`src/`(App/Player/Settings/FileList/DownloadManager/新增 Feeds/ErrorBoundary)、`electron/`(main/preload/torrent-engine/settings/新增 rss/thumbnail-store)、`src/types/index.ts`、`src/services/ipc.ts`、`src/styles/global.css`(新页面沿用现有设计语言,支持亮暗主题)

建议按阶段顺序提交 commit,每个阶段独立可用;阶段 6 工作量最大,若中途想调整范围可随时叫停。
